# Study Buddy content pack format

Content packs are the quiz engine's view of the study material. Each pack is a
plain JS module exporting one object in this shape:

```js
export const packExample = {
  id: "pack-biology-ch6",          // unique pack id
  chapterId: "chapter-6",          // course chapter id
  title: "Chapter 6 — Bones and Skeletal Tissues",
  system: "Skeletal system",       // default system label for the pack
  chapter: { id, number, title, status },  // verbatim chapter metadata
  bones: [                          // clickable bone targets (chapter 7 pack)
    {
      boneId: "femur",              // matches BodyExplorer onBoneSelect boneId
      label: "Femur",
      regionId: "lower-limb",
      regionLabel: "Lower limb",
      description: "…",
      system: "Skeletal system",
    },
  ],
  terms: [                          // nameable study items
    {
      id: "head-of-femur",
      term: "Head of femur",        // the canonical name (graded answer)
      definition: "…",              // null when no authored definition exists
      chapterId: "chapter-7",
      chapter: "chapter-7",
      system: "Skeletal system",
      boneId: "femur",              // null for non-skeletal terms
      boneLabel: "Femur",
      regionId: "lower-limb",
      regionLabel: "Lower limb",
      viewId: "femur-proximal-anterior",
      aliases: ["…"],               // accepted synonyms
      identifyPrompt: "…",          // clue-style prompt
      location: "…",
      hint: "…",                    // short study cue (never the answer)
      note: "…",                    // longer study note
    },
  ],
  flashcards: [                     // verbatim front/back cards
    { id, chapterId, category, front, back, note },
  ],
  quiz: [                           // pre-authored quiz items, verbatim
    {
      id, chapterId,
      type: "multiple-choice" | "true-false",
      prompt, options, correctAnswer, explanation,
    },
  ],
}
```

## Provenance (zero content loss)

Packs are **derived, not hand-written**, so content can never drift:

- `pack-biology-ch{1,2,3,4,6,8,9}.js` — generated by
  `node scripts/generate-biology-packs.mjs` from `src/data/studyData.js`.
  Flashcards and quiz items are copied verbatim (same ids, same strings).
  `terms` are the chapter `vocabulary` lists (exact strings); their
  `definition` is intentionally `null` because those chapters have no authored
  per-term definitions — inventing them would alter content.
- `pack-bones-ch7.js` — generated by `node scripts/generate-bones-pack.mjs`
  from `src/data/bonesLabChapter7.js` (static parse; the source imports `.png`
  assets that only Vite can resolve). Every structure row becomes a term with
  identical facts; every bone row becomes a `bones` entry. Chapter 7
  flashcards and quiz items are copied verbatim from `src/data/studyData.js`.

After regenerating, run `node scripts/verify-packs.mjs` to confirm
before/after counts match.

## Quiz engine contract (`src/quiz/engine.js`)

The engine is UI-free plain JS. Six deterministic generators (seeded RNG;
same seed ⇒ same question order and distractors):

1. **multiple-choice** — pre-authored items verbatim, plus generated
   term→definition / definition→term items with 4 options.
2. **fill-in-the-blank** — definition with the term blanked to `______`
   (quiz items: prompt shown, exact answer typed).
3. **connect-the-statements** — matching: N cues ↔ N answers, both sides
   shuffled; graded as a mapping.
4. **click-the-bone** — emits `{ boneId, label }` targets; the UI feeds
   `BodyExplorer`'s `onBoneSelect` payload (`selection.boneId === target.boneId`).
5. **type-the-bone-name** — typed recall against term + aliases.
6. **name-the-system** — "which system does X belong to?" with system options.

### Study vs blind

`buildSession(pack, mode, { studyMode: "study" | "blind" })` — every question
carries `prompt` (the ask, never contains the answer) plus:

- `study`: `info` is included — definitional cues, hints, notes, region/bone
  labels that help learning without revealing the graded answer.
- `blind`: `info` is `null` — only the bare prompt is shown.

### Progressive hints

Every question carries `hintLevels`, an array of 0–3 strings from vague to
specific. They never contain the graded answer:

1. first letter + letter count, e.g. `Starts with "H" • 13 letters`
2. the authored `hint` / cue (when one exists)
3. structural cue, e.g. `Region: Lower limb • on the Femur` or `N words`

The UI reveals them one at a time on request.

### Spell-check (fuzzy matching)

`gradeTyped(question, input, { spellCheck })` preserves the app's existing
typed-recall tolerance exactly (ported from `bonesLabUtils.evaluateTypedAnswer`):

1. Normalize: lowercase, non-alphanumerics → single spaces, trim.
2. Exact (case-insensitive) match against term or alias → **correct**.
3. Normalized match → **correct** ("casing or punctuation differed").
4. Input matches a *different* structure's term → **wrong-structure**,
   incorrect, flagged for review.
5. Otherwise compute the Levenshtein distance to each accepted term and take
   the closest:
   - **threshold: distance ≤ 2 absolute, OR distance / maxLength ≤ 0.2
     (20% relative)** → verdict **close / misspelled**: incorrect, but flagged
     `close: true` and routed to review ("Close, but the spelling is off").
   - beyond threshold → **incorrect**.
6. Blank input → **blank**, incorrect, "type an answer" message.

With `spellCheck: false` the fuzzy step is skipped: near-misses are graded
plain **incorrect** (no `close` flag). Correct answers always increment the
score; `close` answers never do — same as the existing typed-recall summary.

### Attempts, weak spots, persistence

- `answerQuestion(session, questionId, response)` is pure: returns a new
  session plus feedback; attempts are recorded as
  `{ id, drillRef, mode, correct, close, at }`.
- `deriveWeakSpots(attempts)` aggregates misses into the app's existing
  weak-spot shape: `{ [id]: { misses, lastMissedAt, sources: { engine: n } } }`.
- `mergeEngineProgress(prevState, result)` returns a new localStorage state
  object that **adds** `engineQuizHistory[sessionKey]` (attempts / best /
  last percent) and merges engine weak spots into
  `anatomyProgress.weakSpots` — every other key is carried over untouched, so
  state migrates forward and is never wiped. The storage key stays
  `biol2401-study-hub-v1`.
